¿Qué es y para qué sirve?

Este conector permite al agente de Ruvic publicar mensajes en un tópico de Google Cloud Pub/Sub, crear suscripciones pull sobre ese tópico, y consumir mensajes de una suscripción.

Este conector escribe y elimina datos reales publish_message escribe un mensaje real. create_subscription crea un recurso real en el proyecto. consume_messages confirma (ack) los mensajes recibidos, que no vuelven a entregarse.
OperaciónQué hace
pubsub.publish_messagePublica un mensaje de texto en el tópico configurado
pubsub.create_subscriptionCrea una suscripción pull sobre el tópico configurado
pubsub.consume_messagesConsume y confirma mensajes de una suscripción

Prerrequisitos

  • Un tópico de Google Cloud Pub/Sub ya creado.
  • Acceso a Google Cloud Console para crear una cuenta de servicio.

Configuración en el fabricante

  1. Creá una cuenta de servicio dedicada.

    En Google Cloud Console → IAM y administración → Cuentas de servicio → Crear cuenta de servicio. Generá y descargá una clave JSON.

  2. Otorgá acceso al tópico con mínimo privilegio.

    Asigná los roles "Pub/Sub Publisher" (para publicar) y "Pub/Sub Editor" o "Pub/Sub Subscriber" (para crear suscripciones y consumir), idealmente limitados al tópico específico mediante condiciones IAM.

  3. Anotá los datos necesarios.

    El contenido completo del archivo JSON de la cuenta de servicio, y el nombre del tópico.

Permisos requeridos

PermisoPara qué sirve
Pub/Sub PublisherPublicar mensajes en el tópico
Pub/Sub Editor / SubscriberCrear suscripciones y consumir mensajes
Nota No se otorga el rol "Pub/Sub Admin" a nivel de proyecto completo si es posible limitarlo al tópico específico.

Configuración en Ruvic

Entrá a Settings → Conectores, buscá Google Pub/Sub y pulsá Configurar. Pegá el JSON completo de la cuenta de servicio y el nombre del tópico.

Probar conexión — la plataforma verificará el acceso al tópico para confirmar credenciales.

Verificación

  1. Test de conexión exitoso.

    "Probar conexión" debe responder con éxito.

  2. Prueba mínima con el agente.

    Pedile:

    "Publicá un mensaje de prueba en el tópico."

    El agente debe confirmar la publicación y devolver el message_id.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Credenciales inválidas o sin permiso IAM suficiente"Falta el rol "Pub/Sub Publisher" o "Pub/Sub Editor/Subscriber" sobre el tópico, o la clave fue revocada.
"El tópico no existe o no es accesible"Nombre de tópico mal escrito, o el tópico está en otro proyecto distinto al de la cuenta de servicio.
"Google Cloud Pub/Sub no respondió correctamente"Límite de cuota temporal; reintentá en unos segundos.
consume_messages siempre devuelve una lista vacíaNo es un error: no había mensajes disponibles. Verificá que otro consumidor no esté vaciando la suscripción primero.

Preguntas frecuentes y notas de seguridad

¿El agente puede eliminar tópicos o suscripciones?

No. La cuenta de servicio solo tiene permisos de publicación y consumo; el conector no expone ninguna operación de eliminación.

¿Dónde queda guardado el JSON de la cuenta de servicio?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo.

Rotación de credenciales

Generá una nueva clave para la cuenta de servicio periódicamente desde Google Cloud Console y actualizala en el formulario; luego eliminá la clave anterior.

¿Qué hago si el JSON de la cuenta de servicio se compromete?

  1. Eliminá la clave comprometida en Google Cloud Console → IAM y administración → Cuentas de servicio.
  2. Generá una nueva clave y actualizala en el formulario.
  3. Revisá los Cloud Audit Logs por actividad inesperada sobre el tópico.
Buenas prácticas Usá una cuenta de servicio dedicada con acceso limitado a un único tópico; nunca uses una identidad con el rol Pub/Sub Admin a nivel de proyecto; y evitá consumir mensajes de una suscripción de producción sin confirmar primero con el usuario.
